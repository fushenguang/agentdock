## ADDED Requirements

### Requirement: 许可/来源门

模板 MUST 预置第四道门，回答**「我有没有权利发布它」**——这是既有三道门都不回答的问题：
门① 问「结构是否合法」、门② 问「manifest 是否新鲜」、门③ 问「有没有泄漏宿主身份」，
而**第三方版权与宿主身份是正交的**：一份 `© <vendor>` 声明里没有任何字符属于宿主，
门③ 永远不会看它一眼。

该门 MUST 对**每一个** skill 收集许可证据：目录内的 `LICENSE*` / `NOTICE*` 文件、
`SKILL.md` frontmatter 的 `license` 字段、正文中的版权声明形状。

该门 MUST 默认保守：发现任何第三方许可/版权证据，而该 skill 未被显式登记为
「第三方转发」时，MUST 失败。

对显式登记为第三方转发的 skill，该门 MUST 校验其原许可文件与 NOTICE **确实在场**；
缺失 MUST 失败——转发别人的作品而丢掉其许可文件，本身就是违规。

允许转发的第三方许可 MUST 由一份**可配置的数据文件**声明，MUST NOT 硬编码在脚本里；
该白名单 MUST NOT 默认包含专有许可。

该门 MUST NOT 做法律判断（某条款允许什么），MUST NOT 自动改写任何 skill 的许可或补写 NOTICE。
它的职责是**指出证据与声明不一致**，由人处理。

失败时 MUST 指出是哪个 skill、命中了哪条证据、证据的原文位置。

#### Scenario: 供应商专有的 skill 被拦下

- **WHEN** 某个 skill 目录内含声明「保留所有权利」的许可文件，而仓库声明的许可是宽松开源许可
- **THEN** 该门失败，并指出是哪个 skill、证据在哪个文件

#### Scenario: 登记为转发的第三方 skill 缺少原许可文件时失败（负例）

- **WHEN** 某个 skill 被登记为「第三方转发」，但其目录内没有对应的原许可文件
- **THEN** 该门失败——转发不得丢掉原许可

#### Scenario: 自有 skill 正常通过

- **WHEN** 某个 skill 不含任何第三方许可或版权证据
- **THEN** 该门通过，并在输出中列出它被判定为自有内容

#### Scenario: 白名单是数据不是代码

- **WHEN** 需要改变「允许转发哪些第三方许可」
- **THEN** 只需修改配置数据文件，无需修改门脚本
