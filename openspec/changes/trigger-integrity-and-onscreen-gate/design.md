# design · trigger-integrity-and-onscreen-gate

## D1 · 为什么快照要在 handler **前后同步**取，而不是等 settle

`fire()` 今天的顺序是 `handler(); await waitMs(TRIGGER_SETTLE_MS)`。那 50ms 的等待是**故意**的
（既有注释已写明：触发器只往世界里放东西，真正的效果发生在后续物理步的 overlap 检查里）。

推论：**只要在 `handler()` 调用的前后各同步读一次玩家坐标，中间就不可能有物理步**——
Phaser 的 update/physics 循环跑在宏任务里，同步代码之间不会插入。所以**任何差值都只能是
handler 自己写的**，零假阳性。这是本刀能做成"零容忍等值判据"的全部依据；换成"等 settle 之后
再比较"就会把自然位移混进来，判据立刻退化成需要阈值的模糊判断。

🔴 **不许改成阈值比较**（`Math.abs(dx) > 5` 之类）。阈值一进来，"传送 3 像素"就合法了，而免疫
性与位移大小无关。

## D2 · 只钉 `player`，不禁止 handler 移动其它既有实体

严格版（"handler 不许改动任何既有实体的坐标"）会误伤合法写法——例如「敌人冲向玩家」这类
触发器，移动的是敌人，符合"真实玩家的行为能造成"的原意。

E-15 的免疫性来自**被搬动的是断言的观察主体（玩家）**，不是"有东西被搬动了"。判据因此精确钉在
玩家身上：**handler 同步执行期间，名为 `player` 的实体坐标 MUST NOT 变化。**

## D3 · `player` 从习惯升成契约，且**不许静默失效**

今天 `this.player.name = 'player'` 只出现在 `GameScene.ts:94`，是参考实现的习惯。D2 依赖它，
所以本刀把它写进 spec 与 `AGENTS.md`。

🔴 **游戏没有 `player` 实体时，D2 的检查无声跳过**——这正是本模板第一条纪律禁止的形状
（"能被静默跳过的闸不是闸"，见 `scripts/lib/exit-decision.mjs` 头部对 `unavailable` 为什么必须红
的论证）。处理方式：

- **不判红**（一个没有玩家概念的游戏不该因此失败），
- 但 MUST 在 `.verify-result.json` 里留下可见的一行，写明"未找到名为 `player` 的实体，
  触发器完整性检查未生效"。

**"没生效"必须被看见，这是本条的全部要点。** 它与 `unavailable` 那条论证同源：没跑的闸不能
长得像跑过的闸。

## D4 · BH-2 的边界判据取哪个坐标系（🔴 本刀最大的假红风险）

命名实体是否"仍在画面内"，需要一个边界。两个来源：

| 来源 | 何时对 | 何时错 |
|---|---|---|
| `physics.world.bounds`（参考实现已 `setBounds(0,0,GAME_WIDTH,GAME_HEIGHT)`） | 有滚动相机的横版游戏也对——世界比画布大是它本来的语义 | 游戏没调 `setBounds` 时拿不到 |
| `game.scale`（画布尺寸） | 单屏游戏对 | 🔴 **横版滚动游戏会假红**——世界比画布宽，实体合法地在画布外 |

**决定**：优先 `physics.world.bounds`，拿不到再退回 `game.scale`，并且 `.verify-result.json` 的
detail **必须写明这次用的是哪一个**。不静默、不逃生阀。

⚠️ **如实记下**：退回画布尺寸那条路对**横版滚动**游戏有真实假红风险，本刀不消除它，只让它
可见（detail 里能一眼看出边界从哪来、实体坐标多少）。**这是判据 3（真投一次 Run）不能省的
直接理由**——假红只有在真实产物上才暴露得出来。

对 E-15 两条路都有效：旗子在重力下 `y` 无界增长，无论对世界高度还是画布高度都会越界。

## D5 · A 失败为什么走 `unavailable` 而不是新造一种状态

`decideVerdict` 已经规定三态且 `unavailable` 为红，语义正是"有人要求判定，而我们判不了"。
触发器违规恰好是这个形状——**这条断言从此不能证明任何事**。新造第四种状态要同时改
`exit-decision.mjs`、`.verify-result.json` 契约与 web 侧的镜像消费方（cogito-lib
`gate-templates.ts`），成本与收益不成比例。

## D6 · 发布与生效边界

改动落在模板 → changeset → Version Packages PR → npm → **下一次脚手架**。
🔴 **存量生成项目（含「用话造关」）不会自动拿到**，本刀不追这条尾巴，如实写在 proposal 的
Non-goals 里。

## D7 · 🔴 B 的采样时机是它自己的 E-15（2026-08-19 规划方复核时实测抓到）

第一版实现把 BH-2 的边界判据放在 `inspectPage` 的 1000ms settle 之后**采一次样**。
规划方复核时做了两组变异，结论是**这条判据当时抓不到 E-15**：

| 变异 | 结果 |
|---|---|
| 命名实体**一开始就在界外**（`y = 5000`） | **红** ✅ ——判据逻辑与实体收集都没问题 |
| 命名实体用**现实重力**逐渐下坠（`setGravityY(2000)`，从 `y = 100`） | 🔴 **绿** ——没抓到 |

原因：那 1 秒 settle 大部分被 Boot/Preload 吃掉，`GameScene.create()` 跑完时留给下坠的时间只有
几十到几百毫秒，实体还在界内。**执行者第一次自验时之所以是红，是因为它用了 `setGravityY(100000)`
——模板自身重力是 0，那是把重力开到 5 万倍。那个红证明不了 B 对 E-15 有效。**

🔴 **这条要记下来的不是"忘了等"**：单点采样的判据，**在被验对象逐渐坏掉的过程中天然会提前采完样**
——与 E-15 本身（断言跟着坏掉的对象一起移动）是同一族的病：**判法让它永远通过**。

**修法**：给边界判据一个**明确命名的采样窗口常量**，并在 IA 跑完之后**再采一次**（IA 本来就要跑
数秒真实运行时间，第二次采样零额外成本）。任一次出界即红。

**验收判据同时改硬**：变异验证必须用**现实重力**（`setGravityY(2000)` 量级），
🔴 **不许用把重力开到几万的写法把判据糊过去**。

## D8 · 🔴 D7 的修法本身是错的——观察窗必须自己建立起点，不许复用 IA 的运行时间

D7 开出的修法是"IA 跑完之后再采一次样，零额外成本"。**执行者实测证否，证据确凿**：

```
--- 第一次采样（stateId: "Game"）---
entities: [ {name:"player",…}, {name:"testFallingObject", x:480, y:205.5} ]   // 还在界内
--- 第二次采样（IA 结束后立刻）---
{ "stateId": "GameOver", "entities": [] }
```

根因是**结构性的，不是时长不够**（那次 IA 供给了 3403ms，远超 1500ms 下限）：模板自带的
`assertions.json` 把 `game_over_trigger` 排在最后，该判据的最后一个动作是
`fire('gameover')` → `handleObstacleHit()` → `scene.start('GameOver')`，**Phaser 把 Game 场景
拆掉了**，下坠物（连同 player）在第二次采样里根本不存在。`judgeEntitiesWithinBounds([], …)`
于是**平凡通过**——不是"它没越界"，是"这次采样已经看不见它了"。

🔴 **注意这是本刀第三次撞上同一族的病**：E-15 是断言跟着坏掉的对象移动；D7 是采样赶在对象坏掉
之前；D8 是采样时对象已被拆掉。三次都满足同一个判据——**"被验对象整个消失/损坏之后，判据仍然
会通过"**。规划方（我）连着两次开出的修法都栽在这上面，如实记着。

**改为**：边界判据**自己建立观察起点**，不复用 IA 留下的任何状态——

1. 采样一：页面 settle 后立刻一次（几乎零成本，抓"一开始就在界外"）
2. 采样二：`applyState(<role: gameplay>)` → 等 `BOUNDS_OBSERVATION_MS` → 采样

这与断言运行器既有的 D6 纪律（**每条断言前强制 `applyState`**）是同一条，不是新发明。
代价是每次 verify 多几秒墙钟时间，**换来的是确定性与可复现**——和 `jump()`/`isValidStart()`
当初选择"每条断言自建合法起点"是同一个取舍。

**窗口常量的依据（写进注释，不许当魔法数字）**：世界高 540、margin 48，物体从 `y = 100` 起，
`g = 2000` 时越界耗时 `√(2×488/2000) ≈ 0.70s`。取 `2000ms` 可覆盖到 `g ≳ 250`。
⚠️ **如实写下上限**：比这更慢的漂移本判据抓不到——它是采样判据，不是不变量。

🔴 **被否掉的三个备选，记下来免得再提**：
- 「只在 IA 结束后仍处于 gameplay 时才采第二次」——那是逃生阀形状，本模板明令禁止
- 「IA 期间穿插采样」——把两次采样变成 N 次，且结论依赖清单顺序，不可复现
- 「要求清单最后一条不许离开 gameplay」——`pnpm verify` 管不了项目自己的 `assertions.json`

## D9 · 🔴 拿真实产物验 B 的结果：**没红**——判据看不见那个坏掉的对象

> 2026-08-20 补。判据 3.2（原本挂起等开发机）已执行完，结论是**负的**，如实记在这里。

从 VM 只读取回「用话造关 v2」的真实源码（`/home/workshop/v2-d8ec77a4`），本地叠加本刀的
判据跑 `pnpm verify`：

```
[verify] BH-2 render — passed (... entities within bounds across 2 samples ...)
```

**不是"没越界"，是两次采样里从来没出现过 goal 或刺。** 源码级根因：

| 事实 | 位置 |
|---|---|
| `this.player.name = 'player'` —— **唯一**被命名的实体 | `GameScene.ts:316` |
| `this.goal = this.physics.add.sprite(...)` + `setImmovable(true)`，**从未 `.name`**、也没 `setAllowGravity(false)` | `:320-326` |
| spike 由 `group.create(...)` 生成，**同样没有 `.name`** | `:330-336` |
| 世界重力 `gravity.y = 1200` 非零 | `:256` |

而 `collectEntities()` 明写着 `if (!named.name) continue`。

🔴 **B 的可见范围建立在一条没人保证的契约上（"关键对象要命名"），而那正是散文纪律
——本刀存在的理由就是消灭这类东西。** D3 把 `player` 升成契约时只覆盖了玩家一个，
其余对象的命名仍然全靠自觉。

🔴 **更要记的是验收方法上的错**：本刀的变异验证之所以红，是因为**我自己给测试物体写了
`.name = 'goal'`**——用一个满足契约的样本，验了一条对不满足契约的真实产物无效的判据。
连同 E-15、D7、D8，这是同一族病的**第四次**，而这次犯在验收方法上。

## D10 · ✅ 但 A 在同一份真实产物上是有效的（真红）

同一次叠加里，IA 有两条断言**新变红**：`m-score_feedback` 与 `m-game_over_trigger`
——因为这份游戏的 `handleGoalReached` 正是**把玩家瞬移到目标处**（源码注释自己写着
"teleport the player onto the goal's overlap area"）。

**这是拿真实坏件验出来的真红**，比人工变异硬得多。**E-15 的主防线成立**，
欠的只是 B 这条兜底。

## D11 · B 的修法方向（留给下一刀，本刀不改已发布的行为）

`immovable === true && allowGravity === true` 在 Arcade 里近乎必然是 bug
（E-15 的直接根因就是"immovable 不关重力"），**且这个信号不依赖命名**。
比"要求关键对象都命名"强：后者又是一条要靠自觉维持的契约。

⚠️ 但**不许直接把 `collectEntities()` 改成收集未命名对象**——子弹、金币这类
**合法地**飞出画面，那样会造成大量假红。判据要换的是**信号**，不是放宽范围。
