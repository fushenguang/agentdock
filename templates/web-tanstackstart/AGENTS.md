# AgentDock web-tanstackstart Template — Agent Execution Boundaries

> For AI coding agents working in a project generated from the AgentDock `web-tanstackstart` template.

This is a TanStack Start application that keeps AgentDock's `core` / `features` / `infra` boundaries. Standalone output owns its pnpm files and package-manager declaration. Workspace-member output is detected by `.agentdock/workspace.json`; in that mode the parent workspace root owns installation, lockfile, pnpm version, and build approvals, and the notice at the top of this file overrides standalone installation instructions.

## Read First

Read `LLM.md` before implementation. It contains the stack rationale, architecture, import rules, data flow, feature recipes, UI guidance, and verification workflow. This file defines execution boundaries; `LLM.md` defines how to build within them.

## May Execute Autonomously

- `pnpm install`, `pnpm dev`, `pnpm dev:prepare`, `pnpm build`, `pnpm check`, `pnpm check-types`, `pnpm lint`, `pnpm format:check`, `pnpm test`
- `pnpm generate-routes`
- `pnpm db:generate`, `pnpm db:migrate`, `pnpm db:studio`
- Creating or editing files inside `src/core`, `src/features`, `src/infra`, `src/routes`, and `src/components`
- Adding feature tests and updating `LLM.md`, `DESIGN.md`, or `README.md`
- Running read-only `openspec` commands

## Must Pause And Confirm

- Any `git push`, force push, package publishing, or release operation
- Deleting tracked files or directories
- Adding a new top-level directory
- Adding or upgrading runtime dependencies that are not already in `package.json`
- Changing `openspec/config.yaml`
- Changing `pnpm-workspace.yaml`, `packageManager`, Node engine requirements, or deployment/server entrypoints
- Editing Supabase migrations after they have been applied to a shared environment

## Prohibited

- Writing real secrets, API keys, tokens, or production database URLs
- Importing `infra/db/**` directly from `features/**`; use `core/repositories` and `infra/providers`
- Cross-feature imports that bypass a feature's public `index.ts`
- Importing `features/**` or `infra/**` from `core/**`
- Creating a feature directory without `__contract__.ts`
- Running `rm -rf` on tracked directories
- Bypassing hooks with `--no-verify`
- Editing `src/routeTree.gen.ts`; it is generated by `pnpm generate-routes`

## Architecture

```text
src/routes/       TanStack Start file routes and server-function entrypoints
src/components/   Shared presentation, layout, appearance, and locale controls
src/core/         Stable domain types and repository contracts
src/features/     Product behavior; each feature owns a contract and public index
src/infra/        Drizzle clients, schemas, repository implementations, provider wiring
```

Features are the primary implementation area. Data access flows through a repository contract and the provider in `src/infra/providers.ts`. `infra` changes require human review because they affect persistence behavior.

## Verification

Run the narrowest useful check while iterating, then the full gate before finishing:

```bash
pnpm test
pnpm check-types
pnpm lint
pnpm format:check
pnpm build
pnpm check
```

`pnpm check` is the acceptance command and runs the full local gate.

The standalone project supports pnpm `>=10.34.5 <13` and recommends 12.4.1. The template intentionally has no exact `packageManager` pin or automatic version switching; engine validation stops unsupported versions before install. Workspace members inherit the supported pnpm range from the workspace root.

## UI Rules

- Create every page with `pnpm page:new "<intent>" --route <path>`; never lay a page out from
  scratch. Put the page type last (`mobile settings page`, not `settings page on mobile`). Change
  an existing page only inside its existing sections.
- `pnpm build` fails when a component route has no template provenance marker.
- Use Astryx components for controls and structure; use StyleX only for remaining first-party layout or product styling.
- Prefer native Astryx primitives (`Stack`, `Grid`, `Section`, `List`, `EmptyState`, `Center`, `Timestamp`, and component-specific APIs) over hand-rolled equivalent markup.
- Use Astryx design tokens instead of hard-coded colors, spacing, radii, or shadows when a token exists.
- Change themes through `AppearanceProvider`; use prebuilt Astryx themes and their compiled CSS rather than creating route-local theme stores.
- Add every user-facing string to all catalogs in `src/i18n/messages.ts` and resolve it with `useTranslator()`.
- Keep application pages under the `/$locale` route layout unless a route is intentionally global.
- **Width is the scarcest resource.** This Web is embedded in the App's right-hand panel (~380px, hard minimum 360px), so branch on container queries rather than viewport width and never introduce horizontal scrolling.
- Build a second-level page on `PageShell` (the one-screen skeleton); put configuration, forms and secondary detail in a `SideDrawer`, rare actions in one end-aligned `MoreMenu`, and keep cards to single, independently enterable units — a page is `Section` + `Divider` + rows, not a wall of boxes.
- Do not add Tailwind, CSS-in-JS runtimes, or a second component library without approval.
- Apply the `impeccable` skill before declaring a UI change complete.
