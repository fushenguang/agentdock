# Child Design System Contract

This template keeps Astryx as the component and interaction kernel and adds a first-party Child Experience System. The visual result must feel warm, safe, encouraging, playful, and calm without reproducing a third-party game interface or asset set.

## Sources Of Truth

1. Astryx component semantics, accessibility behavior, and official guidance.
2. Generated child theme source and prebuilt CSS.
3. Semantic Astryx tokens.
4. Child capability presets and `docs/age-profiles.md`.
5. `docs/child-safety.md`.
6. First-party child components and StyleX product styles.

## CSS Layers

Required order:

```text
reset < astryx-base < astryx-theme < product
```

Theme CSS is generated by Astryx. Do not edit generated theme CSS by hand. Product styles must not use `!important` to win a cascade conflict.

## Visual Principles

- Warm cream and paper-like surfaces instead of cold gray.
- Deep warm text instead of pure black.
- Original sunny, mint, coral, sky, and leaf accents used semantically.
- Rounded but purposeful geometry; pills only for controls where appropriate.
- Restrained 3D depth on primary actions only.
- Cards use borders, spacing, and low elevation rather than heavy floating shadows.
- Illustrations are simple, consistent, original, and purposeful.
- Light and dusk modes both preserve hierarchy and contrast.

## Age Adaptation

The theme changes appearance. The capability profile changes support, density, choice count, navigation, reading mode, motion, guidance, confirmation, and timeout behavior.

Feature components must use capabilities, not raw age labels.

## Typography

- Font roles use Nunito Variable for Latin and Noto Sans SC Variable for Simplified Chinese.
- Body weight should remain comfortably readable for children.
- Sprout uses the largest type ramp; Creator uses the smallest but remains at least 16px base.
- Use Astryx `Heading` and `Text`; do not set font size or line height manually in feature components.

## Components

Use Astryx components before raw HTML. First-party child components are semantic wrappers only:

- `KidShell` for the application frame and child navigation.
- `KidPageHeader` for heading, explanation, and one primary action.
- `KidActionCard` for a large navigation/action target.
- `KidChoice` for selection.
- `KidProgress` for effort-oriented progress.
- `KidState` for loading, empty, waiting, error, success, offline, and permission states.
- `KidReadAlong` for optional spoken support with text fallback.
- `GuardianGate` for grown-up confirmation.
- `KidIllustration` for original inline SVG decoration.
- `KidTitleRibbon` and `KidBackground` for non-interactive decorative surfaces.

For the phase-one component ownership map and extension rules, read `docs/component-visuals.md`.

A wrapper may add layout, copy slots, capability adaptation, or illustration. It must not reimplement Astryx focus, keyboard, selection, validation, dialog, or announcement behavior.

## Motion

- Use Astryx duration/easing tokens.
- Motion must help orientation or feedback; it must never block the next action.
- Sprout defaults are gentler than Explorer and Creator.
- All motion paths must work with `prefers-reduced-motion`.
- Avoid flashing, fast parallax, uncontrolled rotation, and repetitive reward animation.

## States

Loading, empty, waiting, error, success, offline, and permission states are part of the design contract. Every state should explain what happened and what can happen next in non-blaming language.

## Content

- Short, concrete, active sentences.
- Icon plus text for important actions where possible.
- Celebrate effort and recovery, not only correct answers.
- Never use shame, fear, urgency, public comparison, streak loss, or random reward loops.
- Keep the same task semantics across age profiles; vary support and presentation.

## Accessibility

- Preserve semantic roles and accessible names.
- Keep focus visible and keyboard paths complete.
- Validate contrast in light and dusk modes.
- Provide text alternatives for audio and illustration meaning when needed.
- Do not rely on color alone.
- Test at 320px upward and across the supported age/locale/mode matrix.
