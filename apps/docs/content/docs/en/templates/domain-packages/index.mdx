# Domain Packages Workspace

The `domain-packages` template initializes a repository that deliberately contains no business package.
It carries OpenSpec, a documentation workspace, the deterministic package generator, machine-readable
schemas, practice pack, and agent skills needed to create a formal domain package without
reconstructing paths from model memory.

## Create a workspace and first package

Interactive `agentdock init` continues from workspace scaffolding into first-package onboarding. It
asks for the domain package id and intent, derives sensible display-name/owner defaults, and creates
the package before returning:

```bash
npx @cogito.ai/cli@0.27.1 init \
  --name my-domain-packages \
  --template domain-packages \
  --dir my-domain-packages \
  --pm pnpm
```

Agent/JSON mode remains non-interactive. Pass explicit package fields or a spec:

```bash
npx @cogito.ai/cli@0.27.1 init \
  --name my-domain-packages \
  --template domain-packages \
  --dir my-domain-packages \
  --pm pnpm \
  --json \
  --domain-package-id example-domain \
  --domain-package-intent "Help the user complete one concrete domain outcome with a reviewable artifact."
```

Omit those fields in agent/JSON mode to generate the valid empty workspace.

## Repository layout

```text
openspec/               # root specification workspace
apps/<package-id>/      # domain package root
apps/<package-id>/web/  # ignored build staging
apps/docs/              # documentation workspace
apps/web/               # package Web source
```

## Use the generator in an existing workspace

Run this in an interactive terminal when the workspace already exists:

```bash
pnpm create:package
```

The generator asks for the id and intent and applies display-name/owner defaults. It does not require
a temporary `package-spec.json`.

## Create a package from a spec (agent/CI)

```bash
cat > package-spec.json <<'JSON'
{
  "id": "example-domain",
  "displayName": "Example Domain",
  "intent": "Help the user complete one concrete domain outcome with a reviewable artifact.",
  "owner": "@team",
  "lifecycle": "active",
  "repositoryClass": "product",
  "hasWeb": true
}
JSON

pnpm create:package --spec package-spec.json
pnpm install
pnpm check
```

The generator creates:

- package `contract.json`, declarations, truth, upgrade metadata, and system prompt;
- package-local `AGENTS.md` and `roadmap.yaml`;
- `agent/surface.json` and `agent/web-surface.json`;
- a capability catalog;
- the fixed `apps/web/` `web-tanstackstart` package Web project;
- root `dev`, `check`, and package build commands.

Formal packages default to Web. A no-Web package requires an explicit approved exception.

## Source and artifact boundary

`apps/<package-id>/web/` and generated seed databases are ignored build staging. A release pipeline must
build them from a clean source clone and include them in an immutable artifact with checksum and
build metadata.

## Agent boundaries

The template is designed for AI coding agents, but intelligence remains external to the package:

- no package-owned LLM calls;
- no second agent loop or conversation memory;
- intent-level Web actions and capabilities, never DOM-selector automation;
- package-local roadmaps and context;
- no copying business implementations between packages.
