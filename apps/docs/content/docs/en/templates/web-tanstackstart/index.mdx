# web-tanstackstart Template

`web-tanstackstart` is an independent, single-package web application template. It keeps AgentDock's semantic `core` / `features` / `infra` boundaries without using a monorepo or Turborepo.

## Technology

| Layer           | Technology                                                  |
| --------------- | ----------------------------------------------------------- |
| Runtime         | Node 22.13+                                                 |
| Package manager | pnpm 10.34.5–12.x (12.4.1 recommended)                      |
| Language        | TypeScript 7                                                |
| Application     | TanStack Start + TanStack Router                            |
| Build           | Vite 8                                                      |
| UI              | React 19 + Astryx (multi-theme + i18n) + StyleX             |
| Data            | Drizzle ORM + SQLite by default, Supabase Postgres optional |
| Quality         | Oxlint, type-aware Oxlint, Oxfmt, Vitest                    |

## Architecture

```text
src/routes/       TanStack Start file routes
src/components/   Shared presentation components
src/core/         Domain types and repository contracts
src/features/     Feature behavior behind __contract__.ts and index.ts
src/infra/        Drizzle schemas, clients, repositories and provider wiring
```

The `/{locale}/hello` reference feature demonstrates:

1. A TanStack server function.
2. A feature use case behind its public boundary.
3. A `core` repository contract.
4. A SQLite implementation by default.
5. A Supabase Postgres implementation with the same contract.

The default UI targets the **App's right-hand panel**, where this Web runs as the auxiliary workbench of the App's coding agent (default ~380px, hard minimum 360px). It is a container-query shell with bottom navigation and no top bar, so no page spends a row repeating the shell:

- a **first-level route is a landing**: a visually hidden `h1`, one line of orientation, and module entries that lead one route deeper;
- a **second-level page uses the one-screen `PageShell` skeleton**: the page itself does not scroll and only its content body does (never wrapped in a card), so the way back never scrolls away;
- configuration and forms go into a right-hand `SideDrawer` (no scrim, it does not close on an outside click), and rare actions go into one end-aligned `MoreMenu`;
- **cards are the exception**: a page is sections and rows, and card chrome is never nested.

Shared layout primitives live in `src/components/layout`: `TemplateShell`, `BottomNav`, `PageContainer`, `PageTopBar`, `PageShell`, `SideDrawer`, and `HorizontalFields`. The shell includes:

- prebuilt Astryx Neutral, Butter, Matcha, and Stone themes;
- system, light, and dark color modes;
- locale-prefixed routes for Simplified Chinese (`/zh-CN`, default) and English (`/en`);
- a `/{locale}/settings` route (the Settings Surface: section navigation plus one scrolling panel) hosting the appearance and language controls, with preferences persisted in a first-party cookie and language switches preserving the current page.

## Agent Guide

The generated project includes `LLM.md`, a single agent-oriented development guide covering technology rationale, dependency boundaries, feature recipes, database changes, UI development, verification, and troubleshooting. `AGENTS.md` remains the execution-boundary contract and points to `LLM.md` first.

## Data Providers

SQLite is the default and requires no external service:

```dotenv
DATA_PROVIDER=sqlite
SQLITE_DATABASE_URL=./data/app.db
```

To use Supabase as a Drizzle Postgres provider:

```dotenv
DATA_PROVIDER=supabase
SUPABASE_DATABASE_URL=postgres://YOUR_USER:YOUR_PASSWORD@YOUR_HOST:6543/postgres
```

The Postgres client sets `prepare: false` for compatibility with Supabase transaction pooling. This template targets long-lived internal Node deployments; it does not provide a serverless SQLite strategy.

The project supports pnpm `>=10.34.5 <13` and recommends 12.4.1. No exact `packageManager` pin is written, so supported pnpm 10/11/12 users do not trigger automatic version switching; `engineStrict` rejects versions outside the range. If the local version is older than 10.34.5, update within the 10.x line or use `npx pnpm@12.4.1`.

## UI

Astryx supplies components, prebuilt themes, the locale catalog, and CSS. The template follows an Astryx-first composition rule: use native Astryx layout, collection, feedback, and content components before adding a thin project wrapper. The official Astryx Vite StyleX integration is configured for the remaining first-party styling. Theme and locale extension rules are documented in `LLM.md` and `DESIGN.md`.

Start with [Usage](./usage), then update `DESIGN.md` when a project establishes its own visual direction.
